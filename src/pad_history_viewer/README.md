# Ion pad-history viewer and CSA compression study

From the repository root:

```sh
python scripts/view_pad_histories.py
```

The default card is `config/pad_history_viewer_direct.toml`, using the corrected
direct-collected 2 mm / 20 ms and 4 mm / 40 ms histories. The viewer labels this
input method explicitly. Historical cards and numerical results are preserved.

The launcher opens a local browser tab. It uses the existing
`work/event-viewer-venv` Python environment when Plotly is absent from the current
interpreter. Dependencies are pinned in `requirements.txt`; Julia uses the root
`Project.toml`. `--no-browser`, `--port`, `--work-dir`, `--simulator` and `--julia`
can select the launch settings. The server binds to 127.0.0.1 and prints its URL.

Select configuration/sample, event ID and pad. The Standard events menu provides
a fixed-seed sample without a confirmed 10%-loss/one-ENC flag in the completed
study; its initial pad is the strongest by minimum linear voltage. The
Demanding histories menu selects extreme candidates. Arrow buttons move between
stored events and pads. All 8000 event IDs remain available.
The three linked panels show collected ions per bucket, CSA output voltage and
charge estimates in elementary-charge units. Zooming one panel updates the time
range of all panels. The default Whole event view includes every original event
bucket. Fit occupied interval spans the selected pad's first to last occupied
bucket, including internal zeros and a small margin. Include recovery adds the
saved three-second tail. The coverage line reports visible original, occupied
and recovery bucket counts. Display toggles retain the chosen time range. Linear predictions, collected counts and the nominal one-ENC band can
be toggled. The displayed mean response includes induction before collection
and centred averaging across boundaries.

Calculate SPICE response runs the complete selected history, preserves the
circuit state through empty buckets, and caches the result. Cached cases reopen
without a simulation. Python serves data and acquires LTspice output; Julia
restores source counts, generates the finite-gap current, propagates the linear
response, integrates voltage windows and measures response loss.

The Compression study tab displays confirmed event fractions at 10%, 25%, 50%
and 75% relative response loss. Its missing-signal control selects zero, one or
three nominal ENC of deficit. A flag requires collected charge in the bucket;
all inputs remain present. This is a distortion study, and does not designate
an event as unusable.

To precompute the initial pads of all standard-menu entries:

```sh
PYTHONPATH=src python scripts/cache_standard_pad_histories.py
```

The browsing selection is generated by `standard_events.jl` and saved to HDF5
with its seed, selection-code hash and source-statistics hash. Additional
browsing simulations leave the completed statistical selection unchanged.

## Statistical pipeline

```sh
PYTHONPATH=src python scripts/run_pad_compression.py --workers 4
```

`config/pad_history_viewer_direct.toml` defines the conservative linear-voltage screen,
fixed-seed controls, severity criteria, current resolution and recovery tail.
The batch simulates every pad below the screen and twelve controls per sample
in each higher-voltage stratum. Empty buckets and the full uncut counts are
retained. All four MC sources contain 8000 events; the configurations reuse the
same diffused events.

The nonlinear and linear predictions use the same averaging and corrected
frame difference. Relative loss compares those predictions, avoiding confusion
between compression and the signal shared by neighbouring buckets. Affected
charge is the number of collected ions in flagged buckets divided by the full
event collected count. Statistical rates count confirmed events in the tested
candidates and controls; controls check the unsimulated range.

Direct-input results are stored in `results/ltspice/pad_compression_direct/<identity>/`. The identity
covers configuration, source-screen, physical-code, circuit/model and calibrated
response hashes. Each source file is checked against its recorded SHA256. Case
HDF5 files retain counts, all sampled outputs, reduced continuous voltages,
criteria and numerical validation. Exact currents and netlists reproduce each
simulation. The three-second tail is included in empty-frame evaluation.

Current-integral checks use the finite-path charge e[1-phi_w(g)]. A failed
exported-current check triggers finer solver steps. The constant baseline is
validated against the saved zero-input transient. A reproducible selection of
candidate and control histories is refined. `--retry-failed` reruns recorded
failures; completed matching cases remain cached.

Julia writes event statistics and the report numerical tables. Python renders
them, with no repeated physical calculation:

```sh
julia --project=. scripts/report_pad_compression.jl RESULTS_DIRECTORY
python scripts/present_pad_compression.py --results RESULTS_DIRECTORY
```

The generated report source and figures are under
`latex_generated/pad_compression_direct/<identity>/`. Compilation follows the user's
instruction to run only on request.

## Interfaces and checks

- `src/ion_signal/pad_compression.jl`: `Context` owns frozen configuration,
  provenance and cached metadata; `catalogue` maps event IDs to contiguous
  source rows; `counts` restores a complete pad sequence; `history` saves its
  linear prediction; `prepare` writes the finite-gap PWL current; `reduce`
  calculates averaged readout and compression criteria; `plan` selects the
  exhaustive candidate set and stratified controls; `aggregate` counts flags
  and affected charge per event.
- `worker.jl`: file-backed TOML requests serialize Julia calculations and
  return saved HDF5 paths. A worker error preserves completed cache files.
- `engine.py`: owns the resident worker, cache lookup and transistor simulator.
  Per-case file locks let the viewer and batch share completed results safely.
- `server.py`: serves the application, typed navigation requests, pollable SPICE
  jobs and saved statistical results. Plotly is served locally.

```sh
work/event-viewer-venv/bin/python tests/pad_history_viewer/check_integration.py http://127.0.0.1:PORT
make test physics PYTHON=/path/to/python
```

The integration checks compare source counts and zero buckets, the earlier
matched-baseline transistor result and the live HTTP API. The Julia report step
checks complete coverage, event accounting, nested thresholds, affected-charge
bounds and refinement convergence.

The scientific question

Given a simulated energy-deposition track in xenon, determine whether its diffused topology forms one connected track and calculate how many positive ions arrive at each sensor pad as a function of time. The saved pad histories supply the charge input for the signal and electronics model in src/ion_signal.

The two input ensembles are double-beta events and single-electron backgrounds. Topology selection and pad-charge distributions are studied together, with selection efficiencies and charge accounting reported for each sample.

Reading order: physics → event flow → reuse strategy → concrete interface drafts → configuration/output → validation. The three appendices retain the inspected Petit source, its original interfaces and the discussion’s decision record.

Bulk transport model

Sample one drift distance L uniformly from 10 to 150 cm per event. Use that L to calculate common diffusion widths for all its hits. Preserve the source coordinates and axis directions. This approximates the event’s transport with a common drift distance; its longitudinal track structure remains in the hit coordinates.

Review finding F1 is resolved: retain this common-distance approximation for the study. The per-hit drift refinement was considered and declined.

Collection and time histories

Use a periodic square collection grid with pitch 2 mm. The selected track supplies a transverse reference; independently shift grid edges in x and y by uniform offsets in [0, pitch). Use the same grid for all slices of that event.

Geometric cell assignment represents the approximation that ions in each collection cell reach its corresponding hole/pad. Pitch determines collection cells; the physical metal pad width is a separate detector dimension. The pad histories are the input to subsequent signal formation through the IFG and pad gap.

Slice the full diffused distribution in 2 mm longitudinal bins. At the configured speed, each bin spans 20 ms. Preserve both spatial and time axes with the per-pad counts. The relative-time origin and drift-axis sign are explicit interface-review items below.

The revised detector design specifies 5 kV across the 10 mm IFG and 3 kV across the 5 mm pad gap. The event-stage Gaussian widths use the bulk field; local transport and weighting-field response belong to the signal calculation.

Graph voxelisation receives the diffusion table; pad counting receives that same original diffusion table. Changes to reconstruction binning therefore affect acceptance, while the accepted event’s charge input stays available at diffusion-histogram resolution.

Charge accounting

N_expected = sum(mean_ions_per_hit)
N_sampled = sum(integer_ions_per_hit)
rounding_difference = N_sampled - N_expected

N_sampled = N_diffusion_retained + N_diffusion_outside
N_diffusion_retained = N_graph_retained + N_graph_below_threshold

# For accepted events with complete pad-axis coverage:
sum(pad_slice_counts) = N_diffusion_retained

These equalities separate rounding, finite diffusion bounds and the graph threshold. Each is saved with its own name. Pad charge conservation uses the full retained diffusion count. Event rejection is recorded as an event decision.

Example: two occupied diffusion cells contribute 6 and 14 ions to different reconstruction bins. At threshold 10, the graph contains the 14-ion bin. If the event passes the one-component condition, its pad histories contain all 20 ions. This is the approved change from Petit’s selected-track occupancy input.

Ensemble reductions

Save per-event energy, total expected ions, mean ions per hit and total sampled ions. A per-event pad history retains its event-specific axes and grid offset. For ensemble maps, the working convention labels the pad containing the selected track’s x/y reference as (0,0). Existing cells retain their integer counts. Arrival bin zero starts at each history’s first saved arrival edge.

Julia sums exact Int64 counts on shared axes covering every cell. Float32 means use two explicit denominators: accepted events, and all processed events with rejected events contributing zero selected charge. Both appear in figures and HDF5. With no accepted events the conditional mean is NaN; the processed mean is zero. Review this working alignment alongside the step-four results.

Development philosophy

This is a focused adaptation of Petit. Copy the required loaded functions, preserve their algorithms and MIT attribution, and make small reviewable changes. Maintain a source map recording the original file, function, source hash and reason for each adaptation. Existing graph and backbone machinery supplies the numerical core.

Deterministic functions derive results from explicit inputs and preserve those inputs. Random sampling receives an explicit RNG. HDF5 access, TOML parsing, execution order and report generation live at the application boundary. Typed parameters carry validated values into computation.

Review each type and function together: purpose, fields/signature, units, ownership, examples and tests. Implement in small increments that produce checkable output. Keep physical assumptions visible beside numerical results.

function validate_bin_table(df::DataFrame)
    for name in (:x, :y, :z, :energy)
        hasproperty(df, name) || throw(ArgumentError("Missing column $name"))
        eltype(df[!, name]) == Float32 || throw(ArgumentError("$name must have Float32 values"))
        all(isfinite, df[!, name]) || throw(ArgumentError("$name must be finite"))
    end
    all(>=(0f0), df.energy) || throw(ArgumentError("energy must be nonnegative"))
    if hasproperty(df, :event_id)
        eltype(df.event_id) == Int64 || throw(ArgumentError("event_id must be Int64"))
        length(unique(df.event_id)) <= 1 || throw(ArgumentError("Expected one event"))
    end
    return nothing
end

ion_counts · implemented docstring
ion_counts(hits::EventHits, ionisation_energy_eV::Float32)

Convert deposited MeV into expected positive-ion counts using the common mean
pair-creation energy W in eV: expected[j] = energy_MeV[j] × 10⁶ / W. Apply
Petit's per-hit `round(Int64, expected[j])` rule (nearest integer, ties to even)
to obtain the counts used for Monte Carlo diffusion. Each ion has charge +e.

Return an owned NamedTuple with expected::Vector{Float32}, sampled::Vector{Int64},
event_energy_MeV::Float32, total_expected::Float32, mean_per_hit::Float32 and
rounding_difference::Float32 = sum(sampled) − total_expected. Reductions use
Float32; the sum of integer counts is checked for Int64 overflow. Rounding is
deterministic. Statistical ionisation fluctuations are a separate model.

W must be finite and positive. Validate current hit values before calculating;
unrepresentable expectations/counts or totals raise ArgumentError/OverflowError.
Preserve the input arrays and row order. Source: Petit transform_hits_df in
src/itaca_functions.jl; explicit W and charge accounting are the adaptations.

function compute_occupancy_analysis(diffused::DataFrame;x_edges_mm::Vector{Float32},
        y_edges_mm::Vector{Float32},z_edges_mm::Vector{Float32},
        drift_speed_mm_ms::Float32,drift_direction::Int)
    total_ions = _diffused_total(diffused)
    foreach(_check_edges,(x_edges_mm,y_edges_mm,z_edges_mm))
    isfinite(drift_speed_mm_ms) && drift_speed_mm_ms > 0f0 || throw(ArgumentError("Drift speed must be finite and positive"))
    drift_direction in (-1,1) || throw(ArgumentError("drift_direction must be +1 or -1"))
    nz = length(z_edges_mm)-1
    time_origin_z_mm = drift_direction == 1 ? first(z_edges_mm) : last(z_edges_mm)
    time_edges_ms = drift_direction == 1 ? (z_edges_mm.-time_origin_z_mm)./drift_speed_mm_ms :
                                          (time_origin_z_mm.-reverse(z_edges_mm))./drift_speed_mm_ms
    _check_edges(time_edges_ms)
    sums = Dict{NTuple{3,Int64},Int64}()
    for row in eachrow(diffused)
        row.ions == 0 && continue
        i = _histogram_index(row.x,x_edges_mm)
        j = _histogram_index(row.y,y_edges_mm)
        z = _histogram_index(row.z,z_edges_mm)
        min(i,j,z) > 0 || throw(ArgumentError("Pad axes do not cover all retained diffusion charge"))
        k = drift_direction == 1 ? z : nz-z+1
        key = (Int64(i),Int64(j),Int64(k))
        sums[key] = Base.Checked.checked_add(get(sums,key,Int64(0)),row.ions)
    end
    counts = DataFrame(pad_ix=Int64[],pad_iy=Int64[],slice_index=Int64[],ions=Int64[])
    for key in sort(collect(keys(sums)));push!(counts,(key...,sums[key]));end
    return (;counts,x_edges_mm=copy(x_edges_mm),y_edges_mm=copy(y_edges_mm),
             z_edges_mm=copy(z_edges_mm),time_edges_ms,drift_direction,time_origin_z_mm,total_ions)
end

        pitch_mm::Float32,z_bin_width_mm::Float32,drift_speed_mm_ms::Float32,minimum_half_cells::Int=40)

Paired drift and ELCC electron readout

User design inputs, 2026-10-29: sample one event location along the 1.5 m TPC. Ion drift is L towards the cathode; electron drift is 1.5 m − L towards the anode. Save both diffused clouds before mapping them through their grids, retaining their common event and ionisation-deposit identity.

The electron grid has cylindrical holes of 5 mm diameter and 5 mm depth, on 10 mm pitch. Geometric collection assigns electrons to holes. The EL field E/P = 3 kV/cm/bar at 15 bar gives E = 45 kV/cm and a 22.5 kV potential rise along electron passage. TOML records entry-grid and exit-anode potentials as 0 and 22,500 V in a relative voltage gauge.

Electrons produce VUV photons along the hole. Calculate the direct optical acceptance analytically and sample that fraction. Save photoelectron histories per SiPM in configurable time buckets. User inputs: 1 μs per mm of drift, initially 2 μs buckets, and SiPM PDE = 0.30 in TOML. For isotropic emission uniformly along the hole axis, an exit-plane SiPM covering the full hole, and absorbing walls, the depth-averaged acceptance is (h + R − √(h² + R²))/(2h), or 0.190983 for R=2.5 mm and h=5 mm. This benchmark specifies an axial electron path. The first implementation holds the fitted EL yield at its mean and samples detected PE with an exact binomial draw using direct acceptance × PDE. PE are assigned to the parent electron's 2 μs arrival bucket.

Source: J. Hikida et al., NIM A 1080 (2025) 170706, papers/ELCC/Axel-ELCC.pdf, Fig. 2 and sections 2 and 4. The paper describes focusing, EL and SiPM readout; its upgraded unit has 4.5 mm holes covered by 4.7 mm round SiPMs. The 5/10/5 mm geometry above is the user's design input. The paper supplies no quantitative EL yield equation or numerical SiPM PDE.

New yield sources: papers/ELCC/NEXT-EL-Xe-He.pdf, Table 1, uses Y = A max(E/P − X0,0) P h. At 15 bar, E/P=3 kV/cm/bar and h=0.5 cm: pure Xe (A=137, X0=0.73) gives 2332.425 photons/electron; Xe–15% He (A=139, X0=0.80) gives 2293.5. These matched fits are the initial configurable prescriptions. Their measurements were near 1.2 bar; application at 15 bar assumes reduced-field scaling.

papers/ELCC/EL-Next-DEMO.pdf, Eq. (2), quotes the conventional pure-Xe A=140, X0=0.83 prescription (2278.5 photons/electron here). Its 2.0–9.4 bar measurements show about 5% relative slope increase above 5 bar, with about 30% absolute calibration uncertainty. It supplies no measured 15 bar or Xe–He correction. See docs/decisions.md for the source audit, uncertainties and the internal percentage discrepancy in the Xe–He paper.

Graph and backbone rules

The radius builder keeps bins with energy ≥ threshold, connects nearby bin centres using a KDTree, splits the graph into connected components, and constructs one Tracks object per component. make_tracks sorts these by deposited energy. The kNN variants use the same component/result structure with a different edge rule.

Diffusion and the later detector stage

In the ITACA batch runner, drift distance is a per-event parameter: either fixed or sampled uniformly between lmin and lmax. The runner computes one pair of diffusion widths from that distance and passes them to the event processor. The active diffusion routine samples one displacement per integer carrier: independent Gaussian x/y displacements with σt and a z displacement with σl. It uses a histogram covering the hit extent plus nsigma × sigma padding. Only samples inside that histogram are counted. The resulting histogram is then rebinned by the ordinary voxelisation routine.

The current ion branch of get_sigma sets σt from the thermal formula and σl to zero. Its drift argument is in cm; returned widths are in mm. itacaScripts/itaca_simple_reco.jl already calculates pixel occupancy for events with exactly one reconstructed track. Its sequence is optional diffusion → voxelisation → graph construction → single-track occupancy.

OperationActual implementation
GridCentre a square pixel grid on the energy-weighted track barycentre. The caller defaults to a 160 mm grid; pixel width is max_distance, or voxel_size when max_distance is infinite.
Longitudinal slicesStart at the track’s minimum z and use 2 mm slices. The time conversion appears only in a comment assuming 1 mm/ms; the calculation itself bins z.
Ion assignmentFor each retained track voxel, add energy_MeV × 10⁶ / 22 to the pixel containing its x,y centre in the current z slice. This is square-cell collection with fractional expected counts.
ResultsReturn total, average, maximum and nonzero minimum pixel-count matrices over slices, occupancy per slice and signal summaries above 10 ions. Each slice matrix is temporary; the full pad-by-slice distribution is not returned.
Collection modelThe event calculation assigns charge geometrically to pixels. A separate archived scripts/scriptBkup/mipa.jl prototype traces fields from a hole to a disk; it is independent of this event occupancy calculation.

The occupancy calculation uses the selected track’s energy after the graph’s bin-energy threshold. Its average matrix is an average over slices of one event. Sampling an ensemble requires an additional event accumulation.

Concrete adaptation checks: use one configured W-value consistently (the diffusion routine defaults to 40,000 carriers/MeV, equivalent to 25 eV, whereas occupancy uses 22 eV); test grid coverage and upper-bin boundaries. With the current half-open z slices, an exact integer-multiple z extent puts its maximum on the excluded final edge. Preserve the per-slice counts for our output.

Integer carrier conversion: approved

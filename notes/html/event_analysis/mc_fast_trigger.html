1. Event selection and frame definition

Gamma veto: there must be no gammas with deposited energy greater than 3 keV outside the event frame. If there is one, the veto triggers. The energy threshold is set in the card.

  • Read the MC hits and mother particles.
  • Place the event in the detector.
  • Apply the detector containment cut.
  • Apply the vertex fiducial cut.
  • Apply the gamma outside frame veto.
  • Pass the accepted event and its frame to detector transport and electronics.
  1. Sample the primary vertex uniformly over detector Z = 0–1500 mm. Translate the whole event together.
  2. Require every deposited hit within that detector-Z interval. Only contained events enter the efficiency denominator.
  3. Require the primary vertex within 50–1450 mm.
  4. Build the main-track box from the primary electrons and their delta-electron descendants. Exclude particles produced through a gamma. Add 20 mm on each side in X, Y and Z to define the event frame.
  5. Reject the event if the gamma veto triggers.

Detector dimensions, frame margins and the gamma energy cut are parameters which can be set by card (TOML).

A gamma deposit is the sum of the energy deposited by that gamma and the particles it produces. The main track contains the primary electrons and their delta-electron descendants. An electron produced through a gamma belongs to that gamma deposit.

EventFrame

struct EventFrame
    frame::CoordinateFrame
    lower_mm::NTuple{3,Float32}  # X, Y, Z
    upper_mm::NTuple{3,Float32}  # X, Y, Z
end

An axis-aligned box with inclusive bounds. The main-track box, gamma bounds and expanded acquisition frame share this type. Trigger functions use mc_vertex_frame. Require finite coordinates and lower ≤ upper on every axis; a zero-width primary extent is valid.

GammaDeposit

struct GammaDeposit
    gamma_particle_id::Int32
    energy_keV::Float32
    bounds::EventFrame
end

The first gamma’s particle ID, the sum of deposited energy of its descendants, and their hit bounds. Only deposits with positive summed energy enter this vector. Event number comes from MCEventInfo. Gamma deposited energies are summed in Float32, as are the hit energies.

FastTriggerSettings

struct FastTriggerSettings
    chamber_length_mm::Float32
    vertex_z_min_mm::Float32
    vertex_z_max_mm::Float32
    margin_mm::NTuple{3,Float32}  # X, Y, Z; applied to each side
    gamma_energy_cut_keV::Float32
end
  • Chamber length: 1500 mm.
  • Vertex interval: 50–1450 mm.
  • Margins in X, Y and Z: 20 mm on each side.
  • Gamma energy cut: 3 keV.
  • Detector Z starts at zero.
  • The chamber length must be positive.
  • The vertex interval must lie within the chamber, with its lower bound no greater than its upper bound.
  • Margins and energy cut must be finite and nonnegative.

FastTriggerDecision

@enum FastTriggerDecision::UInt8 begin
    trigger_accepted = 0
    outside_detector = 1
    outside_vertex_fiducial = 2
    outside_frame_gamma = 3
end

The first failed cut, in that order, or acceptance. Add enum values as new cuts are introduced, keeping existing numeric values stable in saved files. Events with outside_detector are excluded from normalization.

FastTriggerOutput

struct FastTriggerOutput
    decision::FastTriggerDecision
    frame::EventFrame
end

The selection decision and expanded acquisition frame. The caller retains the event information and placement. Diagnostic reports keep gamma deposits and rejection details separately.

FastTriggerStatistics

struct FastTriggerStatistics
    input_events::Int64
    outside_detector_events::Int64
    outside_vertex_events::Int64
    outside_frame_gamma_events::Int64
    accepted_events::Int64
end

Disjoint decision counts for one sample. Normalization = input − outside detector. Vertex survivors = normalization − outside vertex. Final efficiency = accepted / normalization. The gamma-cut efficiency is accepted / vertex survivors. Zero denominators produce an undefined efficiency, displayed as “—”; counts remain valid.

3. Coordinates and event placement

center_hits(hits::MCEventHits, info::MCEventInfo)::MCEventHits

Subtract the generation vertex from every hit, placing the vertex at (0, 0, 0).

place_event(rng::AbstractRNG, event_id::Int64,
            chamber_length_mm::Float32)::EventPlacement
  • Sample the vertex uniformly along the chamber.
  • Ion drift is Z.
  • Electron drift is chamber_length_mm − Z.
  • Add Z to each centred hit’s Z coordinate to obtain its detector position.
  • EventPlacement stores the drift distances in cm.

5. Processing one event

  1. Read the settings. Load the detector length, vertex interval, frame margins and gamma energy cut from the TOML card.
  2. Read the event. Load its number, generation vertex, primary-particle IDs, MC hits and mother particles from HDF5.
  3. Move the generation vertex to zero. Call center_hits to subtract the generation vertex from every hit.
  4. Choose the event position. Call place_event to sample Z uniformly along the chamber. This gives the ion and electron drift distances. Use the same position for both.
  5. Run the fast trigger. Call mc_fast_trigger. It finds the main-track box, adds the frame margins and calculates each gamma deposit. It checks detector containment, computes the vertex position, applies the vertex fiducial cut and applies the gamma veto. It returns the decision and frame.
  6. Update the counts. Call update_statistics. Count the event as accepted or rejected by the first cut it fails. Events outside the detector are excluded from the efficiency denominator.
  7. Save the selection result. For every event, save its number, sampled position, decision and frame. Save the main-track box and gamma deposits for the analysis plots.
  8. Continue with accepted events. Pass their hits, position and frame to the ion and electron transport calculations. The frame defines the region to be read out. Record how much charge falls outside it, including after diffusion.

Read the MC event

hits, info = read_mc_event(hit_file, event_id)
particles = read_mc_particles(raw_file, Int64[event_id])[event_id]

Function calls

hits_at_vertex = center_hits(source_hits, info)
placement = place_event(rng, info.event_id,
                        settings.chamber_length_mm)
output = mc_fast_trigger(hits_at_vertex, info, particles,
                         placement, settings)
stats = update_statistics(stats, output)

After processing the sample

  • Save the number of input events, the number rejected by each cut and the number accepted.
  • Calculate efficiencies using only detector-contained events as the starting sample.
  • Save the TOML settings and random seeds with the HDF5 results, together with the input-file and code versions needed to repeat the calculation.
  • Read those results in Python to produce the HTML tables, distributions and example events.

6. Tests

TestWhat we check
Gammas producing other particlesCount each hit’s energy once.
Primary electrons and delta electronsInclude primary and delta-electron hits in the main-track box, regardless of particle numbering or order. Exclude gamma-produced electrons.
Gamma depositing energy inside and outside the frameUse the gamma’s total deposited energy when applying the cut.
Frame edgeA hit exactly on the frame edge must not reject the event.
Detector containmentReject an event with a hit beyond the detector’s 0–1500 mm Z interval.
Vertex fiducial cutAccept a vertex at 50 or 1450 mm (5 or 145 cm). Reject vertices beyond that interval.
Energy cutKeep the event if every gamma outside the frame deposits 3 keV or less. Reject it if any deposits more.
Gammas inside the frameKeep them regardless of energy.
Order of cutsCheck detector containment, then vertex position, then outside gammas. Count each rejection at the first failed cut.
Moving an eventMove every hit by the same amount, preserving the track’s shape and size.
Event countsExclude outside-detector events from efficiencies. Processing in batches gives the same counts.
Comparison with the prototypeBoth programs give the same frames, gamma energies and accepted events at the same settings.
Data checksLeave input data unchanged and report missing or inconsistent particle information.

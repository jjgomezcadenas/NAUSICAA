Ion CSA v3 pilot: agreed interfaces

The 100-event-per-sample, 3 mm/30 ms pilot was approved in the conversation. It measures S/N as signal quality and applies no S/N cut.

Existing input

EventAnalysis.read_ion_history reads nausicaa.ion_pad_history.v1 into an owned IonPadHistory. Its sorted SparseCells columns contain signed Int64 pixel and bucket keys with positive ion counts. GridSpec records mm geometry; the detector card supplies ms frame width. The reader checks unique keys and exact ion accounting.

Adaptation

The response consumer groups the existing sparse columns by pad, preserving their input and signed bucket keys. It restores zero frames from the event minimum bucket through the maximum plus a recorded recovery window. Counts remain Int64. Physical calculations use Float64 SI; Float32 output rounding is checked against these references.

NoiseStationary Gaussian frame noise, temporally correlated according to the filtered one-sided SPICE spectrum, independent across pads. Seeds depend on source/configuration, sample, event and pad and remain independent of worker count and pilot size.
Output eventPreserves event ID, placement, reference/phase and pair checksum; stores pad coordinates, first signed bucket, dense pad/frame counts, mean and noisy recovered ions, sampled mean voltages, model flags and compression diagnostics.
Response fileAtomic versioned HDF5 with explicit selected IDs, source event count, source hash, resolved cards, calibration and covariance. Complete means all requested pilot events and validation ledgers passed.
Summary and HTMLJulia reduces the HDF5 response to histograms, per-event quality, compression and charge bias. Python presents saved results and selected histories without repeating the physical calculation.

Controls

Reproduce the existing 20/40 ms v3 results; derive 30 ms from the same circuit. Check one-ion finite-path charge, covariance/variance, zero-input histories, temporal alignment, carryover, fast-versus-transistor response, timestep refinement and exact input ledgers. The pilot uses pixels with charge and separate zero-input controls; spatial noise occupancy awaits a finite readout area.

Production integration and saved ion matrices

The approved integration uses the existing Julia physical response and three-frame inverse. A Julia production entry point resolves the CSA and reconstruction cards, optionally runs the existing acquisition pipeline, validates the corrected files against the upstream ion histories, and publishes immutable response nodes plus a run manifest. Python launches LTspice and presents saved numerical results.

InterfaceData and behaviour
IonCSAProduction.read_event(path, event_id)Returns an owned ReconstructedIonEvent: signed Int64 pad coordinates and first bucket, Int64 input counts, Float32 mean/noise/reconstructed matrices in Julia frame,pad order, Float64 time edges in s and per-frame noise sigma in ion charges. Checks shapes, units, positive-input channel selection, ion ledger and additive reconstruction.
IonCSAProduction.validate_response(path)Checks selected event IDs, upstream content hash, exact sparse-to-dense count replay, pair checksums and corrected frame covariance. Rejects incomplete, mismatched or unsupported files.
IonCSAProduction.run(root, card)Resolves existing corrected studies or executes the existing filtered-response and reconstruction runners. Publishes validated ion response files atomically and saves the graph manifest. Event selection and circuit/noise identities remain those of the numerical backend.
Acquisition policyA compact list of pixels receiving at least one input ion, each with every bucket in the event acquisition interval, including empty and quiet buckets. A distant deposit adds its occupied pixels without filling the spatial rectangle. Absent pixels received no input charge and their electronic noise was not simulated. Signed estimates are preserved; measured zero suppression belongs to later analysis.
Production schemanausicaa.ion_csa_response.v1 copies the validated corrected matrices without numerical changes and adds explicit acquisition-policy and parent-response metadata. The run manifest references each versioned response and its upstream source, selected events, configuration and checksum. Future combined manifests can reference these ion nodes alongside the SiPM branch.

Controls compare the published numerical arrays with the corrected parent, replay all upstream positive cells including signed bucket keys, check zero buckets and widely separated pixels, retain negative noise and validate covariance diagonals. Tests include incompatible-card and changed-source rejection.

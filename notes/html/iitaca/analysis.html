iItaca analysis

From the hit files of a run to its selection table, its statistics and the comparison of signal and backgrounds.

1. Order of the cuts

  1. Fast trigger, applied when the batch is read (simulation chain): detector, distance to the EL entry, frame, gamma veto.
  2. ROI cut: event energy strictly between the bounds of the energy card, Qββ ± roi_width_fwhm × FWHM / 2.
  3. Track selection on the ion lattice (track selection), with the settings of the tracks card.
  4. Separation of one electron from two: the cut on E₂, or the classification network (classification network).

Steps 2 and 3 are columns of the feature table, so their thresholds can be studied without reading the events again.

2. Feature table of a batch

prepare_iitaca_features.jl reads hits.h5 of a batch and writes features.h5 beside it (schema iitaca.features.v1), one row per event accepted by the trigger. The settings are those of the resolved configuration stored in the hit file.

With --tracks-variant=<variant card> the selection and the features use the tracks card of that variant, which may differ from the variant of the hit file only in tracks.* (same saved hit cut). The table is written to the batch folder of the run of that variant (the variant name replaced in the run label), with a link hits.h5 to the shared hit file. The readout is run once for both track settings.

  1. Copy the event columns of the hit file (hit file) and the trigger counts.
  2. in_roi: the ROI cut on energy_keV.
  3. Track selection (TrackSelection.track_selection): segments, deposits, deposit_keV (largest detached deposit), segments_joined, selected.
  4. Main track (TrackSelection.track_features): hits above the hit cut, components, main_keV, second_keV, main_voxels, length_mm, extent_x_mm, extent_y_mm, extent_z_mm, and the endpoint energies E1_keV ≥ E2_keV.

3. Statistics of a run

prepare_iitaca_statistics.jl joins the feature tables of the batches of a run into statistics/events.h5 (schema iitaca.statistics.v1) with the summed trigger counts and the cut flow; present_iitaca_statistics.py writes statistics/index.html.

Step of the cut flowEvents
generatedgenerated in Geant4, from generated_events_per_batch of the run card when stated
readin the input files (for the gamma samples, those saved by the energy window of the generation)
triggeraccepted by the fast trigger; the rejected ones are listed per decision
roiof those, event energy in the ROI
trackof those, selected by the track selection

The page shows the cut flow, the energy deposited, emulated and reconstructed from the ions, the segments and detached deposits of the events in the ROI, the endpoint energies and length of the selected tracks, and the drift length, hits and noise.

4. Signal against backgrounds

prepare_iitaca_comparison.jl takes the statistics of a signal run and of one or more background runs of the same variant, ROI and track settings, and writes comparison.h5 (schema iitaca.comparison.v1); present_iitaca_comparison.py writes the page.

  1. Cut flow of each run, side by side.
  2. For the events in the ROI that pass the track selection: E₁ and E₂.
  3. Cut on E₂: an event is accepted when E₂ exceeds a threshold. For signal efficiencies of 90, 80, 70 and 60 % the threshold is the corresponding quantile of the signal; each background gets its accepted fraction with its binomial error.
  4. The curve of background acceptance against signal efficiency for every threshold, and its area.

6. Tests

  • tests/track_selection/test_track_selection.jl: each rule of the selection on a synthetic 3 mm lattice; the saved ITACA feature tables reproduced exactly.
  • tests/iitaca/test_iitaca_analysis.jl: the cut on E₂ on known samples; on the pilot read with the ITACA ion settings, the selection and the track features equal the itrack columns of the ITACA feature tables, event by event; the cut flow is consistent with the tables; a sample compared with itself gives no separation; the feature table of a tracks variant equals the selection recomputed with its settings, and a variant that changes the readout or the saved hits is refused.

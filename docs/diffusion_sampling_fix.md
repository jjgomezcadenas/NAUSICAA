# Diffusion sampling bug and correction

## Resolution adopted 2026-10-29

The implementation follows the user's storage decision: sample each carrier
and increment its physical pad/EL-hole and longitudinal bucket in the same
Julia pass. It does not cache individual coordinates or regenerate a display
histogram. `scripts/sample_collect_parallel.jl` writes version-2 ion/PE HDF5
histories in `results/grid_readout_direct_8000/`; the older binned files remain
for audit. Electron bucket width is specified as 2 mm in TOML and corresponds
to 2 microseconds at the configured speed. The proposal below records the
original coordinate-cache option considered during the audit.
The original interactive pad viewer now replays sampled carriers for its
physical pad/time view. The ion-only batch histories at 2, 3 and 4 mm have
been regenerated in versioned `*_direct` directories. Existing electronics
acquisitions from older binned histories retain their historical inputs.

## Implemented correction

Direct carrier sampling and immediate physical-grid assignment are implemented
in `scripts/sample_collect_stream.jl` and `scripts/sample_collect_parallel.jl`.
The earlier ion-only pixel interface is regenerated by
`scripts/run_pixel_charge_direct.jl`. The implementation uses deterministic
replay where needed and does not persist individual carrier coordinates. It
removes the intermediate histogram from the readout calculation.

The electronics rerun uses the corrected 2 mm and 4 mm pixel histories through
`config/pad_history_readout_direct.toml` and
`config/pad_history_viewer_direct.toml`. Its comparison report is
`latex_generated/pad_history_direct_comparison/report.tex`. Historical inputs
and electronics results remain preserved.

The sections below record the diagnosed path and original implementation
proposal; the deployed direct-assignment program replaces the proposed
coordinate cache.

## Diagnosed historical path

The historical readout pipeline uses a histogram-reduced diffusion image as the physical
carrier cloud. Its fixed 100 cells per axis can become wider than the detector
pixels or time slices. Sampled carrier positions are then lost before collection.
This affects x, y and z, including ions and both electron gas models.

The proposed correction preserves the sampled coordinates through propagation
and cached storage, then assigns those coordinates directly to the physical
readout grid. Histogramming remains a presentation or explicit reconstruction
operation. This option was superseded by the direct sampling-to-grid design.

## Concrete diagnosis

The saved single-electron event 3790 has longitudinal diffusion sigma about
1.47 mm. Its MC deposits span approximately one metre. The padded diffusion
histogram has 100 z cells of width about 10.12 mm, followed by collection into
2 mm slices (20 ms at 0.1 m/s). This can concentrate carriers into separated
arrival buckets and individual transverse pixels. The long relative arrival
interval also follows the event geometry; fixing the discretisation will not
remove the spatial separation of its deposits.

The reproducible audit is `scripts/audit_history_time.jl 3790`; its numerical
record is `results/ltspice/history_time_audit/event_3790.h5` and its report source
is `latex_generated/history_time_audit/event_3790/report.tex`.

## Proposed implementation

1. Add a coordinate-preserving diffusion operation in `src/event_analysis`.
   For each source hit and sampled carrier count, retain the actual Gaussian
   draws as separate Float32 x/y/z vectors in mm. Preserve source coordinates,
   existing diffusion prescriptions, units, seeding and Gaussian draw order
   within each workflow. Keep source EventHits and their identifiers unchanged.
2. Save the resulting carrier coordinates in per-event compressed HDF5 datasets.
   Preserve event/sample/carrier identity, shared event placement, drift lengths,
   sigma values, seeds and source/configuration/code hashes. Document retention
   or truncation explicitly and keep produced/retained/outside accounting exact.
   A change to the finite-window policy is a separate physical choice.
3. Change `propagate_cloud_stream.jl` to save that representation. Its physical
   output must be independent of the display histogram's `nbins` setting.
   Chunk or stream event storage so memory remains bounded; benchmark storage
   and runtime before rerunning every stream.
4. Change `collect_cloud_stream.jl` and the grid collection interface to consume
   actual coordinates. Each retained carrier contributes one unit to the pixel
   or hole and arrival bucket containing its position. Preserve the established
   event reference, random grid phase, drift direction and optical model.
5. Build display histograms separately from the saved coordinates. Explicit
   reconstruction voxelisation may still be used where the reconstruction
   algorithm requires it; it must not feed coarsened positions back into readout.
6. Give the new coordinate representation a new HDF5 schema and cache identity.
   Reject incompatible old inputs. Generate new clouds from source hits and new
   pad/SiPM histories from those clouds; old cell centres cannot be repaired.

A fixed fine sparse histogram could provide an approximation with a documented
convergence study. Direct coordinate assignment removes that extra resolution
parameter from readout and allows the same cloud to be reused for different
physical grids.

## Other callers requiring review

The shared function is also used by:

- `scripts/run_pixel_charge.jl`, lines 46–48; collection consumes `d.bins` at line 54.
- `scripts/pixel_diffusion_cache.jl`, which persists occupied cell centres and
  reloads them as the transport table. Its current compression preserves the
  binned values exactly, but not the original individual positions.
- `src/event_viewer/transport.jl`, lines 24–25; its pad view consumes that output.
- The step-two/step-three validation, ensemble scans and historical Petit
  comparison fixtures. Keep the explicit binned reference tests, and add tests
  for the new physical path rather than changing the meaning of those fixtures.

Correcting only the new worker will not repair the older pixel files currently
used by the CSA viewer. Those histories also need regeneration through the
corrected transport and collection path. Preserve the existing runs for audit.

## Acceptance checks

- Recover configured Gaussian means, widths and covariances from the sampled
  coordinates, using independent Float64 references where appropriate.
- Verify charge conservation and exact retention accounting through HDF5 and
  collection, including zero-charge buckets and weak deposits.
- Use fixed/replayed draws for two spatially separated deposits. With the
  physical collection grid and reference held fixed, changing display binning
  must not change any pixel or arrival assignment.
- Validate collection against an independent assignment of supplied coordinates,
  including points near pad and time-bin boundaries.
- Confirm cache round trips and results are unchanged by process scheduling.
- Revisit event 3790 plus compact events, then regenerate both ion pitch/frame
  configurations and repeat the compression study. Record any Float32 versus
  Float64 boundary-assignment differences against the readout noise scale.

The existing tests establish histogram replay, Gaussian statistics for compact
clouds and charge conservation. Those properties can pass while a long event
is too coarsely represented for readout; an extended-event regression is needed.

Before introducing the revised cloud interface, record its representation and
consumer changes in the existing HTML review guide, following the project's
interface-review convention.

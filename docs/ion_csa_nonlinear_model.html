Fast nonlinear CSA response

Validated implementation, 2026-11-05. The fast nonlinear backend is now the default for new production within its validated domain. Production uses SPICE for out-of-domain histories. Validation mode repeats SPICE controls. Generated validation report · PDF.

Purpose and existing flow

A pad's full ion history generates a finite-gap input current. The current pipeline predicts its linear voltage history; a minimum below 0.63 V selects transistor simulation. The saved voltage is averaged over 5 ms windows, discharge-corrected and passed through the three-frame inverse reconstruction. The new model replaces selected transistor simulations while retaining these input, sampling, reconstruction and stationary-noise conventions.

Implemented model

Let x = Vbaseline − Vout be accumulated voltage excursion, and u = I/e the input current in elementary charges per second. Propagate

dx/dt = gain(x) * u(t) − recovery(x)
Vout(t) = baseline_V − x(t)
x(0) = 0

Gain is measured in V per elementary charge; recovery is in V/s. Both are continuous piecewise-linear tables fitted to SPICE waveforms. The baseline is an equilibrium: recovery(0)=0. Positive gain and nonnegative recovery encode signal accumulation and return towards baseline. The small-signal response is checked against the saved calibration. RK4 integrates the state on intervals bounded by input-current knots and requested output times.

This one-state description passed checks on complete held-out histories, including quiet tails and compressed signals. Leaving the fitted domain selects SPICE for the complete history.

Calibration and independent checks

  1. Extract current, voltage, event identity and source/calibration hashes from saved acquisitions. Stratify calibration histories by signal excursion and history shape. Split by event so no event contributes to both fit and validation.
  2. Fit the local evolution law, then propagate full histories from equilibrium. Do not use true SPICE state to initialize individual validation buckets.
  3. Compare the final corrected estimates against SPICE, with the existing 0.5 ENC maximum bucket-error target, event-charge bias and maximum-pulse statistics.
  4. Test timestep refinement, linear-limit analytic solutions, recovery, state/domain handling, preservation of inputs and voltage-window integration.
  5. Begin with 4 mm / 40 ms bb0nu and assess the available 20/30 ms histories before declaring coverage of those configurations.

Production modes and provenance

Fresh-output per-event scaling separates calibration, compilation and presentation from event processing. The earlier 28.46 s run reused a filtered response; use the fresh benchmark for production estimates.

100-event production-mode timing and response report.

Run cards select mode = "production" or mode = "validation". Production is the default for new runs: it reuses the validated model without generating SPICE control or refinement histories. Validation repeats those comparisons. Both modes retain charge, provenance, noise, reconstruction and storage checks. Production executes the numerical stages in one Julia process and records separate stage timings.

hybrid_spice retains linear predictions above the 0.63 V guard and SPICE below it, plus controls. hybrid_nonlinear uses the same guard and substitutes the validated nonlinear model below it. Out-of-domain histories use SPICE. Model identity includes calibration contents, circuit and solver provenance, model code and selected numerical settings. Each history records its actual backend. Existing response files remain immutable.

The production default is hybrid_nonlinear. Reference runs can explicitly choose hybrid_spice. Noise is generated by the existing covariance model.

Set mode = "validation" and response_model = "hybrid_spice" at the run-card top level to select the reference mode. The optional nonlinear_calibration path defaults to results/ion_csa_nonlinear/v1/calibration.h5. The resolved card pins its SHA256. Saved-study registration and historical low-level acquisition cards retain their recorded interpretation.

The adapter ion_csa_nonlinear_io.jl checks the calibration, circuit and input-current prescription. nonlinear_cases evaluates candidate histories and saves separate predictions for SPICE controls; validate_nonlinear_controls checks their corrected bucket errors. HDF5 model_used codes are 0 linear, 1 SPICE and 2 calibrated nonlinear. The production interface, signed arrays, covariance and charge ledger are retained.

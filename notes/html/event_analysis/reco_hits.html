Event energy and hit output

Processing one event

  1. Read the signed reconstructed ion and PE vectors.
  2. Correct PE for mean attachment using the event drift distance and electron lifetime.
  3. Sum all signed charges to obtain the total reconstructed ions and corrected PE.
  4. Calculate the two event energies: ions × W; corrected PE × W / (PDE × EL yield × optical acceptance).
  5. Rebin the electron vectors to the spatial resolution set in TOML.
  6. Form itrack and etrack hits. Apply the hit-energy cuts, with an absolute minimum of 1 keV.
  7. Write the event totals and retained hits. Release the event vectors.

The event energies are calculated before the hit cuts. The saved hits support new graph calculations and plots without repeating the detector or electronics simulation.

Data types

SavedHits

struct SavedHits
    x_mm::Vector{Float32}
    y_mm::Vector{Float32}
    z_mm::Vector{Float32}
    energy_keV::Vector{Float32}

Retained itrack or etrack hits in vertex-relative coordinates. The existing ReconstructedHits calculation also carries charge; the saved type contains these four columns.

EventEnergy

Signed event totals before hit cuts. Convert the existing calculation results to Float32 for storage.

    electron_hit_cut_keV::Float32

Both cuts must be at least 1 keV. Retain hits whose energy is greater than the selected cut.

HitFileMetadata

Production HDF5 output

One file per selected detector and electronics configuration, containing itrack and etrack for every event.

GroupSaved values
eventsMC event number, ion and electron drift distances, acquisition frame.
eventsTotal reconstructed ions, corrected PE, ion energy and electron energy before hit cuts; reconstruction status.
itrackx_mm, y_mm, z_mm, energy_keV and event offsets.
etrackx_mm, y_mm, z_mm, energy_keV and event offsets.
configurationCards, units, coordinate convention, hit cuts, source checksums and code identifiers.
  • Hit columns use Float32. Event offsets use Int64.
  • Concatenate the hits in event order. The offsets delimit each event in the four arrays.
  • Use chunked, compressed datasets and bounded writes.
  • Raising the hit cut or changing kNN settings uses the saved hits. Lowering the saved cut requires reconstruction again.

HDF5 layout

hits.h5
  schema = "itaca.reconstructed_hits.v1"
  events/
    event_number                        Int64[N]
    ion_drift_cm, electron_drift_cm      Float32[N]
    frame_x_min_mm, frame_x_max_mm       Float32[N]
    frame_y_min_mm, frame_y_max_mm       Float32[N]
    frame_z_min_mm, frame_z_max_mm       Float32[N]
    ion_sigma_t_mm, electron_sigma_t_mm  Float32[N]
    ions, corrected_pe                  Float32[N]
    ion_energy_keV, electron_energy_keV  Float32[N]
    invalid_ion_buckets                  Int64[N]
    invalid_electron_buckets             Int64[N]
  itrack/
    offsets                             Int64[N+1]
    x_mm, y_mm, z_mm, energy_keV          Float32[ion_hit_count]
  etrack/
    offsets                             Int64[N+1]
    x_mm, y_mm, z_mm, energy_keV          Float32[electron_hit_count]
  configuration/
    run_label, species, gas_mixture
    coordinate_frame = "mc_vertex_frame"
    position_unit = "mm"
    energy_unit = "keV"
    cards/, checksums/
    ion_hit_cut_keV, electron_hit_cut_keV
    compression_level, chunk_hits, max_output_bytes
  • Offsets are zero-based cumulative hit counts. Event row j uses Julia array indices offsets[j]+1:offsets[j+1], or the corresponding Python slice.
  • An empty track has equal successive offsets.
  • Append events in input order. Event numbers need not be consecutive.
  • Chunk and compress numeric datasets using shuffle and deflate. Initial settings: 65,536 hits per chunk, compression level 4.
  • Write hits.h5.tmp, check it and atomically rename it to hits.h5. An existing completed file is preserved.

The run label includes the ion and EL pitches. Graph calculations and presentation do not modify hits.h5.

Size

At the current 1 keV cut, itrack and etrack together require approximately 40 MiB per 1,000 events before compression, or 320 MiB for 8,000 events. Event totals and offsets add less than 1 MiB per 1,000 events.

Production and debugging

[hit_output]
ion_hit_cut_keV = 1.0
electron_hit_cut_keV = 1.0
compression_level = 4
chunk_hits = 65536
max_output_bytes = 16777216  # 16 MiB for the 100-event validation

[controls]
mode = "none"

With mode = "none", write only hits.h5. Keep event counts, timing and failures in the run log. Do not allocate, fill or save control histograms, projection matrices, endpoint comparisons or graph scans.

[controls]
mode = "debug"
event_limit = 10
diagnostics = ["noise", "hit_cut"]

Allowed diagnostic selections: noise, hit_cut, graph_scan and electronics_examples. Construct only the requested controls, for at most the specified number of events. Save them under debug/.

Energy distributions and event views are generated separately from hits.h5. They require no production control histograms.

File-size guard

  • Each retained hit contributes 16 uncompressed bytes. Per-event columns and both offsets contribute approximately 100 bytes per event.
  • Allow an explicit reserve for configuration text, compression chunks and HDF5 metadata.
  • The 100-event validation uses a 16 MiB cap, compared with approximately 4 MiB of expected hit data.
  • Check free space and the output size while appending. Stop and remove the temporary file if the cap is exceeded.
  • Use the existing guarded-file checks and 1 GiB free-space reserve.

100-event validation

  1. Run 100 bb0nu events with the current detector and electronics settings and controls.mode = "none".
  2. Check that the output contains only events, itrack, etrack, configuration and the schema identifier.
  3. Read every event back and compare its retained hits and totals with the values passed to the writer.
  4. Report event count, hit count, compressed size and simulation, writing and reading times.
  5. Generate plots afterwards from the completed file.

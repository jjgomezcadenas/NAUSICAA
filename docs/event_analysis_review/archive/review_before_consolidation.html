Binning convention and settings

voxelize_event uses a zero-anchored cubic grid in the coordinates it receives. On each axis it computes floor(Int, x / voxel_size). The representative position is the geometric bin centre (index + 0.5) * voxel_size. It adds all deposited energies in each occupied bin and returns those bins as rows of a DataFrame.

The graph-MC branch passes the original event coordinates directly. Grid alignment is implicit in this convention. The MC-reference helper uses the same integer-bin rule but represents each consecutive group by an energy-weighted position; it serves a different purpose from the graph input.

Graph and backbone rules

The radius builder keeps bins with energy ≥ threshold, connects nearby bin centres using a KDTree, splits the graph into connected components, and constructs one Tracks object per component. make_tracks sorts these by deposited energy. The kNN variants use the same component/result structure with a different edge rule.

The combined backbone finder uses the following decision order. Its confidence values are algorithmic scores used by these branches.

StepDecision in find_extremes_combined
Topology firstUse degree-one vertices and BFS paths; if topology confidence ≥ 0.85, return that path.
Density splitDense means average degree 2E/V > 6.0 by default.
Dense graphTry energy-weighted edge costs, then energy-based endpoints. An early result is accepted for confidence ≥ 0.85 or length > 1.1 × topology length. Then compare spatial and curvature candidates; an optional MST fallback participates before final length comparison.
Sparse graphAccept topology at confidence ≥ 0.8; otherwise use the curvature path if it is more than 1.1 × the topology path length.
Weighted edgesUse distance^α / (mean endpoint energy + ε)^β. Weighted Dijkstra double sweep selects endpoints and a weighted-shortest path.
MST comparisonBuild a minimum spanning tree using Euclidean edge lengths, then double BFS on that tree; report the physical length of the returned path.

Diffusion and the later detector stage

In the ITACA batch runner, drift distance is a per-event parameter: either fixed or sampled uniformly between lmin and lmax. The runner computes one pair of diffusion widths from that distance and passes them to the event processor. The sampled distance sets the widths; this code leaves the hit coordinates in their original frame. transform_hits_df changes table columns and adds carrier counts; it performs no spatial translation.

The active diffusion routine samples one displacement per integer carrier: independent Gaussian x/y displacements with σt and a z displacement with σl. It uses a histogram covering the hit extent plus nsigma × sigma padding. Only samples inside that histogram are counted. The resulting histogram is then rebinned by the ordinary voxelisation routine.

The current ion branch of get_sigma sets σt from the thermal formula and σl to zero. Its drift argument is in cm; returned widths are in mm. The other loaded routine, select_events_itaca, instead sets σl = σt for ions. The pixel/slice occupancy calculation in the simple reconstruction script is described below.

EventInfo

Event-level information: ID, generation vertex and primaries.

Implemented · integration pending review

Purpose

One record per event. Electron-background events have one primary electron; double-beta events have two. The generation vertex defines the origin for local coordinates, and the primary IDs support truth-history studies.

Declaration

end

Fields & contract

FieldJulia type / unitsMeaning and constraint
event_idInt64 · identifierThe source event ID; zero and gaps are valid. Unique within its source sample.
vertex_mmNTuple{3,Float32} · mmFinite (x, y, z) in the source frame; shared by the generated primaries.
primary_particle_idsVector{Int32} · identifiersIDs read from the MC particle table: one entry for an electron background, two for double beta. Unique and sorted.

Worked example

# Electron background: one primary
electron_info = EventInfo(
    Int64(43),
    (10.0f0, 20.0f0, 100.0f0),
    Int32[1],
)

# Double beta: two primaries
info = EventInfo(
    Int64(42),
    (10.0f0, 20.0f0, 100.0f0),  # source-frame vertex, mm
    Int32[1, 2],                 # illustrative IDs, read from MC particles
)

Illustrative particle IDs. The reader supplies the actual IDs for each event. The following hit and centring examples use the double-beta record, event 42.

Validation & ownership

  • The vertex is finite and common to the generated primaries.
  • The primary-ID vector is nonempty and contains unique IDs from the MC particle table.
  • Construction copies the supplied ID vector.
  • Sample identity is stored with the enclosing dataset.

Primary ID ordering

Construction stores a sorted copy of the primary IDs. Their count is the vector length.

Event-level information: source event ID, common primary generation vertex and
primary particle IDs. Electron-background events have one primary electron;
double-beta events have two.

# Fields and arguments
- `event_id::Int64`: event identifier within its source sample. Zero and gaps
  are valid; sample identity is supplied by the enclosing dataset.
- `vertex_mm::NTuple{3,Float32}`: finite source-frame coordinates `(x, y, z)` of

EventHits

One event’s hits, stored as parallel vectors.

Implemented · integration pending review

Purpose

The event ID is stored once. Coordinates, energy, MC time and particle/hit IDs share a common ordering: entry j in each vector describes hit j. The numerical hit fields use Float32.

CoordinateFrame · enum

CoordinateFrame identifies the coordinate system used by EventHits.x_mm, y_mm and z_mm. Julia’s @enum declaration creates the type and its named values:

@enum CoordinateFrame source_frame vertex_frame
ValueCoordinate convention
source_framePositions in the original simulation coordinate system, as read from the NEXUS hit table.
vertex_framePositions relative to the event’s true generation vertex: source position minus vertex position. The vertex is at (0, 0, 0).

The enum is declared with the shared types in src/event_analysis/types.jl.

The field hits.frame holds one enum value. center_hits takes an event in source_frame and returns one in vertex_frame. The coordinate, energy, time and identifier vectors are fields of EventHits.

Read the enum docstring
CoordinateFrame

Coordinate system used by the `x_mm`, `y_mm` and `z_mm` vectors in [`EventHits`](@ref).
The `@enum` declaration defines this type and its two values:

- `source_frame`: positions in the original simulation coordinate system.
- `vertex_frame`: positions relative to the event's true generation vertex,
  obtained by subtracting that vertex from each source position. The vertex is
  at `(0, 0, 0)` in this frame, with the source axis directions preserved.

The field `hits.frame` records the coordinate system. [`center_hits`](@ref)
maps a source-frame event into the vertex frame. Distances are expressed in mm
in both frames.

# Example
```julia
frame = source_frame
@assert frame isa CoordinateFrame
@assert frame != vertex_frame
```

Design notes

Array ownership

Construction copies each array separately; functions return independently owned outputs.

Accumulation precision

Float32 is the proposed baseline for reductions. Compare event-energy sums with Float64 references and report the error relative to 12.5 keV, corresponding to 0.5% at 2.5 MeV, before finalising reduction routines.

Julia documentation

Read the source docstring
EventHits(event_id::Int64, frame::CoordinateFrame,
              x_mm::Vector{Float32}, y_mm::Vector{Float32}, z_mm::Vector{Float32},
              energy_MeV::Vector{Float32}, time_ns::Vector{Float32},
              particle_id::Vector{Int32}, hit_id::Vector{Int32})

One event's hits stored as parallel, independently owned vectors. Entry `j` in
each vector describes the same hit. The same concrete type represents source
and vertex-centred coordinates.

# Fields and arguments
- `event_id::Int64`: event identifier within the enclosing source sample.
- `frame::CoordinateFrame`: coordinate system of the three position vectors;
  see [`CoordinateFrame`](@ref).
- `x_mm`, `y_mm`, `z_mm`: Float32 coordinates in mm, each with length `N`.
- `energy_MeV`: length-`N` Float32 vector of deposited energies in MeV.
- `time_ns`: length-`N` Float32 vector of MC deposition times in ns.
- `particle_id`, `hit_id`: length-`N` Int32 identifier vectors. The pair is
  unique within the event; `(event_id, particle_id, hit_id)` identifies a hit
  within its sample. Hit IDs may repeat across particles.

# Ownership and validation
Construction preserves hit ordering and copies every vector separately, even
when several arguments refer to the same array. All vectors have the same
positive length. Physical values are finite; energy deposits are nonnegative.
The constructor accepts the declared field types.

Throw `DimensionMismatch` for unequal vector lengths. Throw `ArgumentError`
for an empty event, nonfinite physical values, negative energy or duplicate hit
identities. Array contents remain mutable and are validated at computational
boundaries.

# Example
```julia
hits = EventHits(Int64(42), source_frame,
    Float32[10, 13], Float32[20, 24], Float32[100, 102],
    Float32[0.001, 0.002], Float32[0, 0.5], Int32[1, 2], Int32[0, 0])
@assert hits.x_mm == Float32[10, 13]
@assert hits.hit_id == Int32[0, 0]
@assert length(hits.energy_MeV) == 2
```

Julia documentation

Read the source docstring
center_hits(hits::EventHits, info::EventInfo) -> EventHits

Express each hit relative to the event's true generation vertex, preserving the
source axis directions and hit ordering.

# Arguments
- `hits::EventHits`: one event in `source_frame`. Its `x_mm`, `y_mm`, `z_mm`,
  `energy_MeV` and `time_ns` fields contain Float32 vectors in mm, MeV and ns;
  `particle_id` and `hit_id` contain Int32 vectors with the same length.
- `info::EventInfo`: matching event ID, finite Float32 generation vertex in
  source coordinates, and distinct primary particle IDs.

# Returns and arithmetic
A new `EventHits` in `vertex_frame`. Each axis is translated in Float32:
`x_mm = hits.x_mm .- info.vertex_mm[1]`, and likewise for y and z. Coordinates
retain Float32 precision, so comparisons under arbitrary translations use a
tolerance consistent with the source coordinate spacing.

Energy, MC time and identifiers retain their exact values and ordering. Hit
identity remains `(event_id, particle_id, hit_id)` within its source sample.

# Ownership and determinism
The result depends on the supplied arguments. Inputs retain their values and
every returned array is independently owned, including the preserved fields.

# Errors
Throw `ArgumentError` for mismatched event IDs, an input frame other than
`source_frame`, an empty event, invalid physical values, duplicate hit identities
or empty/duplicate primary IDs. Translated coordinates must remain finite.
Throw `DimensionMismatch` for unequal hit-vector lengths. Current array contents
are validated on entry because array fields are mutable.

# Example

VoxelGrid(size_mm::Float32, origin_mm::NTuple{3,Float32})

Specify an axis-aligned cubic grid for hit aggregation.

# Arguments
- `size_mm`: finite positive side length in mm.
- `origin_mm`: finite (x, y, z) corner of cell (0, 0, 0), in mm and in

The integer key on each axis is floor((coordinate - origin) / size).

The constructor stores immutable Float32 values. Throw ArgumentError for

  5. Calculate the geometric cell centres.
  6. Return independently owned arrays, preserving the input values.

voxelize_hits(hits::EventHits, grid::VoxelGrid) -> VoxelCloud

Bin one event's hits into cubic cells and sum their deposited energies.

# Inputs and output
`hits` supplies finite Float32 positions in mm, energies in MeV and unique
(particle_id, hit_id) identities. `grid` defines the grid in hits.frame.
Return a VoxelCloud carrying hits.event_id, hits.frame and grid.

# Assignment and ordering
On each axis, the cell key is floor((coordinate - origin) / size). Lower cell
boundaries are inclusive and upper boundaries exclusive. Sort occupied keys
lexicographically. Store geometric cell centres as Float32 positions in mm.

# Energy reduction
Every hit contributes its energy once, including zero-energy deposits.
Within a cell, visit hits in (particle_id, hit_id) order and accumulate in
Float32. This fixes summation order under input permutations. Validate errors
against independent Float64 reference sums before accepting this reduction.

# Ownership and errors
Inputs retain their values; output arrays are independently owned.
Validate current hit-array contents on entry. Throw DimensionMismatch for
unequal hit-vector lengths. Throw ArgumentError for invalid values or
identities, or cell keys/centres outside their representable range.

# Worked example
With 1 mm cells at origin (0, 0, 0), x=[0.25, -0.25, 0.75, 1.0] mm and
y=z=0.25 mm, return x centres [-0.5, 0.5, 1.5] mm.
For energies [0.001, 0.002, 0.003, 0.004] MeV, the cell sums are approximately
[0.002, 0.004, 0.004] MeV, with Float32 rounding.
